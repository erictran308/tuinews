# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

tuinews: a terminal RSS reader for one person's own use, laid out as tuitube is (`../tuitube`: a sidebar, a grid of cards with real pictures, both arrow keys and vim keys), with a reader for articles' text. Rust, ratatui, tokio, MIT. Its groundwork is tuitube's, copied and cut down: `text::clean`, `config` (the private data folder), `screen` (taking the terminal and handing it back), `tmux`, `proxy`, `theme` and `themes/`, `icons`, `images`, `ui/effects.rs` and `ui/splash.rs` (its logo tuinews's own), `pepper` (less what tuinews doesn't use) and `player` (trimmed to one video's playing: no sound alone, visualizer, chapters, Now Playing cover, subtitles); `typed` (what's typed in a box and its cursor, drawn as a block by `ui::with_cursor`) went the other way, and is the same in both. Keep them in step with tuitube's when one changes; tuitube's CLAUDE.md says why each rule is there.

On a first start it asks (`App.welcome`, `ui::welcome`) whether to start with Vietnam's biggest news sites (`defaults.rs`, `FEEDS`) and categories made of those sites' sections (`CATEGORIES`: each section a feed of its own, not `listed`). `y` puts them in the store once each (`Store::seed_defaults`, the `meta` rows `seeded` and `categories_seeded`), so what you remove doesn't come back; `n` starts with none and the add box open (`Store::start_empty`: the same rows); quitting first asks again (`Store::is_new`). `a` adds a feed (in a category view, only into it), or the feeds of the OPML file whose path it's given, in any view (`opml.rs`, `Store::import`: its folders become categories, empty ones too; a file with no feeds imports nothing), and `tuinews --export [FILE]` writes them out (`opml::write`: each category a folder, a site's section marked `tuinews:section` so it comes back one), `x` in the sidebar removes one, `F` puts one in categories.

## Running

Use a separate data folder for trying things: `TN_DATA_DIR=$HOME/tn-test cargo run` (a full path; relative paths are refused). For checks, prefer tests that render into ratatui's `TestBackend` (`ui/mod.rs` tests, `app::tests::app()`: an in-memory store with the defaults and three articles, pictures offline). To see the real app without a terminal, run it in a pty with `TN_IMAGES=blocks` (any mode but `auto` skips ratatui-image's terminal query, whose thread keeps reading stdin when nothing answers, and takes the first keys typed). `docs/hero.png`, the README's picture, is one frame of made-up sites and articles (`hero.rs`, test-only; nothing real in it): `cargo test -- --ignored export_hero_screen` writes `target/hero/screen.json` (every cell, and where each card's picture went with the kind it is), and `tools/hero.py` draws it as Ghostty would (JetBrains Mono, Nerd Font icons, box lines to the cell edges), painting each picture itself. Tests that talk to the news sites are `#[ignore]`d: `cargo test -- --ignored live` fetches every default feed and reads an article's text from every site. No test starts mpv or pepper-play, opens a browser (`app::open_url` does nothing under `cfg(test)`) or writes Pepper's sequences: a playback in a test is `app::tests::play` (a `Player::pretend`), and `App::video_placement` returns what would be written. To see a video play without a window or sound, point `TN_MPV` (or, with `PEPPER_PORT` set, `TN_PEPPER_PLAY`) at a script that runs `/opt/homebrew/bin/mpv "$@" --vo=null --ao=null --force-window=no`: the line under the video counts its time, and in Pepper's place the pty's output carries the `OSC 777;pepper` sequences.

## Commands

```sh
cargo build
cargo test                       # offline tests
cargo test -- --ignored live     # every default feed, and an article's text from each site
cargo clippy --all-targets       # keep it warning-free
cargo fmt
```

Release binaries are built only by `.github/workflows/release.yml` (pushing a `v*` tag), as tuitube's are: six targets (Linux with musl, static, for any distribution; macOS; Windows with a static C runtime; x86_64 and ARM64 each), tests run on the native ones, then the GitHub release gets the archives, `SHA256SUMS` and a provenance attestation covering both, with the tag's message for notes (`git tag -a vX.Y.Z -F notes.md`). `cargo binstall tuinews` takes those archives (`[package.metadata.binstall]` in `Cargo.toml`), so asset names and the `v<version>` tag must stay as `pkg-url` expects, and the release must be up before `cargo publish` (run with `CARGO_TARGET_DIR` set elsewhere: a `target/package` build leaves later ones stale). Running the workflow by hand only builds, as the run's artifacts.

## Security

Everything from a feed or a page is untrusted: titles, summaries, links, picture URLs, dates, HTML, image bytes.
- Links (an article's, a picture's, a feed's you add or an OPML file lists) are kept only through `article::checked_link`: `http`/`https`, a named host (`article::public_host`: no IP address however it's spelled, `localhost`, `.local`, `.lan`, `.internal`, `.home.arpa`), no user or password, at most `MAX_LINK`. Pictures are fetched only over https (`images::allowed`; `feed::picture_url` asks for https and for the JPEG behind an `.avif`). Redirects (`feed::client`) go only where `checked_link` lets a link go, never from https to http, at most `MAX_REDIRECTS`. An article's page is fetched only over https, only when it's opened, only if it's HTML, at most `html::MAX_PAGE`; feeds at most `feed::MAX_FEED`, pictures `images::MAX_BYTES`.
- OPML: read only from a path typed or pasted in the add box (`opml::path_in`), only a regular file (not a folder or a pipe), at most `opml::MAX_OPML`; only an outline's `xmlUrl` is read (an `include` isn't followed), its names through `article::one_line` after `html::summary`, its folders as category names under the same caps (`MAX_CATEGORY_NAME`, `MAX_CATEGORIES`, `MAX_FEEDS`). Written (`--export`) with its attributes escaped (`opml::escape`), into a new file only, 0600 (`opml::save`: never over one there), or to stdout.
- Text: titles, sources, bylines through `article::one_line` (after `html::summary`, so markup and entities become text, twice-escaped ones too); summaries and articles' text through `html` (only text comes out: `SKIPPED` elements dropped, lists left out of summaries) and `article::lines`, with caps (`MAX_TITLE`, `MAX_SUMMARY`, `html::MAX_BODY`, `MAX_BLOCKS`). Text read back from the store is cleaned again (`store::article_row`, `Block::decode`), and a row whose id or link doesn't check out is skipped. A link in an article is text; nothing opens it. Only `o` (and Enter in the reader, with no video shown or playing) opens a browser, with the article's checked link (`app::open_url`: `open` on macOS/Windows, `xdg-open` found as an absolute path elsewhere, its own process group, the home folder).
- Ids: `ArticleId` is the first 16 hex digits of the link's SHA-256, checked when read back (`ArticleId::parse`); cached pictures are named by it only (`a-<id>`).
- Pictures are decoded only as JPEG, PNG, WebP or GIF (`images::decode`), within `MAX_SIDE` and an allocation cap, WebP frame headers checked first (`check_webp`), a decoder's panic contained (`images::panic_is_contained`, checked by the panic hook).
- No cookies, no `Referer`, timeouts on every request; one proxy for everything (`proxy`: http or https only, else tuinews won't start; a value that isn't text is refused too, never taken for none).
- Videos: an article's are kept only through `html::video_url` (`checked_link`, then https, then a file or playlist by its name, `VIDEO_FILES`), from a `<video>`, VCCorp's `type="VideoStream"` (`data-vid` a host and a path), or the page's data (`application/ld+json`, schema.org's `VideoObject`, only where it's the page's own: at its top, in its `@graph`, or an entity's `video`; at most `MAX_DATA` read, `MAX_VIDEOS`), posters through `feed::picture_url`; checked again when read back (`Block::decode`). One plays only on Enter (`App::play_video`), through mpv (`player.rs`, as tuitube's: `--no-config --load-scripts=no --terminal=no --ytdl=no --tls-verify=yes`, controlled over a socketpair as fd 3, nothing about the video on the command line on Unix, `tools::starting` held while the socketpair is made, `QUIT_GRACE` then killed through its handle), with FFmpeg's demuxers only (`--demuxer=lavf`: mpv's own playlist reader would play a playlist's entries from anywhere) and its protocols to https on both layers (`player::PROTOCOLS` as `protocol_whitelist`: `--stream-lavf-o` for the stream layer, which opens the address and follows its redirects, a redirect to http refused; `--demuxer-lavf-o` for an HLS playlist's parts; never `httpproxy`, which a proxy would need: a playlist's `httpproxy://` part is fetched straight, around the proxy, in plain text; measured on VnExpress's, Dân Trí's, VTC News's and Thanh Niên's streams to play, and an http part, a redirect to http or a playlist of other files to be refused, a redirect to `tcp://` not followed, and that `httpproxy://` part let through when it was listed), `--load-unsafe-playlists=no`, and `--demuxer-lavf-propagate-opts=yes` (mpv's default, set so it stays: certificates are checked for an HLS playlist's parts too, measured to refuse one on a host whose certificate doesn't check out). The hosts of a stream's redirects and of an HLS playlist's parts aren't checked (`public_host` isn't FFmpeg's): mpv makes https requests where they say, certificates checked; closing that would take a CONNECT-only loopback proxy checking each host. With any proxy set, no video plays (`App::play_video` says why): mpv can't be kept to it. Its environment is `tools::player_env`: a child's and its window's and sound's variables (`PLAYER_KEPT`), no proxy. mpv's messages are read a line at a time as bytes (`player::next_line`: at most `MAX_LINE`, what isn't UTF-8 replaced, so one odd line doesn't end the rest). `app::open_url` takes `tools::starting` on macOS and Windows too. In Pepper (`App.pepper`, `pepper::port`: `PEPPER_PORT`, not in a multiplexer) with `inline_video` on and pepper-play found (`Tools::find`: `TN_PEPPER_PLAY`, else `PEPPER_PLAY`), pepper-play plays it instead, with `PEPPER_PORT` added; the token tying its picture to its box (`pepper::new_token`) goes to it only over the socket, and to Pepper only in tuinews's own `OSC 777;pepper` sequences (`pepper::place`, `pepper::remove`, written after a frame by `write_to_terminal`), which carry nothing but the token and cell numbers (holes only to a Pepper whose `PEPPER_FEATURES` lists `holes`).
- Pastes: only bracketed pastes and runs of different keys at once (`App::on_terminal_events`, `PASTED_KEYS`; not a run of keys that only move, arrows, Enter or Backspace, which a slow link sends together) are pasted text; they go in an open box, or open the add box with what looks like a link, never run as keys.
- The store (`tuinews.db`, 0600, `secure_delete`, a WAL checkpoint after removals) and `settings.toml` (written through a rename, one key at a time: `Settings::save_one`) are in the private data folder.

## Architecture

**Event loop (`app.rs`, `App::run`).** One `tokio::select!` over terminal events, `AppEvent`s (`Fetched`, `Page`, `Found`, `Opml`: an OPML file read on a blocking thread, `Image`, `Player`: what the video's player said, `Quit` on SIGHUP/SIGTERM) and a 1 s tick (status messages expire, feeds checked every `CHECK_EVERY`). After each wake, `needs_reload` reloads the view; after each frame, `App::video_placement` tells Pepper where the video goes, and `Images::fetch` starts what the frame wanted.

**Feeds (`feed.rs`).** `refresh_feeds` fetches every feed older than `refresh_minutes`, `PARALLEL` at once, with its ETag and Last-Modified (`Fetched::Unchanged` on 304); a 429 pauses the feed for `SLOW_DOWN`. `parse` reads RSS 2.0, RSS 1.0 and Atom with quick-xml leniently (a mistake keeps what came before it), and Tuoi Tre News's own shape (`article` items, `headline`, a picture in `source`). Pictures come from the enclosure, `media:content`, `media:thumbnail`, `thumb`, then the first `img` of the description or content. Dates (`parse_date`): RFC 2822 with the zones Vietnamese sites write (`+07:00`, `+07`, `GMT+7`, two-digit years, written-out months), RFC 3339, and zoneless ones (Tuổi Trẻ's `10/24/2026 6:26:00 AM`) taken as Vietnam's time for a `.vn` site; a Vietnamese feed whose newest is hours ahead is put in Vietnam's time (`in_vietnams_time`: one of Tuoi Tre News's servers writes `+0000`). A feed carrying whole articles (`content:encoded`, Tuoi Tre News's `content`) gives their text too (`Item.body`, kept as if read from the page). `discover` adds a feed from a site's page (`html::feeds_named`).

**Store (`store.rs`).** SQLite: `feeds` (place, when fetched, ETag, Last-Modified, the last error, `listed`: under Feeds and in Home, else a section only in categories), `articles` (one per link, the feed that brought it first and its source name, published, first seen), `article_feeds` (every feed that brought each article: VnExpress's newest and its Xe section bring the same ones; with the article's date, indexed by feed and date), `categories` and `category_feeds` (a feed in any number), `read`, `saved`, `history` (`HISTORY_SIZE`, cut back once `HISTORY_SLACK` over), `bodies` (articles' text, `Block::encode`). A view of feeds lists its newest (`newest`: Home's and a category's `HOME_SIZE`, a feed's `FEED_SIZE`, each article once), and unread counts count those, less what a blocked word hides (`Store::hide`: the connection's own `temp.hidden`, found once at start and as articles come), so the sidebar's count is the view's. A date ahead of now is now. Removing a feed (`forget_feed`) takes it out of its categories, keeps the articles another feed brought or you saved or opened, and points an article it brought first at another; a section left in no category and not `listed` is removed (`forget_if_orphan`: after `set_in_category` off, `delete_category`). Category names are unique in any case, Unicode's, at most `MAX_CATEGORY_NAME`. `migrate` brings version-1 and -2 databases up (the `listed` column, `article_feeds` filled from `articles.feed_id`, its dates and index; `meta` `version`). Articles older than `keep_days` and in neither list are pruned at start. `Listing` names what a view lists (Home: articles of `listed` feeds); search is done here, over the newest `SEARCHED`, with `article::fold` (lower case, accents off).

**Views.** `View::{Home, Saved, History, Feed, Category, Search}`; `App::reload` rebuilds `App.feeds` (every feed; `App::listed` those under Feeds), `App.categories`, `App.home_unread` (`refresh_counts`) and `App.articles` from the store, leaving out blocked words and (with `unread_only`) what you've read, except what you read since the view opened (`read_here`), and keeps the selection on the same article, or on the newest while it's at the top, and the sidebar's row on the same category or feed (`row_of`). `App::show` switches views, pushing the old one on `back`.

**Categories popup (`F`, `App.category_menu`, `ui::category_menu`).** For the sidebar's feed, else the selected article's (`App::feed_of`: in a category view, the article's feed in that category, from `Store::feeds_of`), else none: the categories ticked where the feed is, then "New category". `Enter` / `Space` toggles (`toggle_in_category`; with no feed, opens the category), `n` names a new one (with the feed in it), `r` renames, `x` deletes after a `y` (`Confirm::DeleteCategory`, as `x` on a category in the sidebar). A name being typed (`Naming`) takes pastes, and counts as typing for `on_terminal_events`; one that won't do stays to be fixed.

**Reader (`App.reader`, `ui/reader.rs`).** A popup over the articles (`ui::reader_place`: `reader_width` + 12 wide, a row free above and below; the whole body below `NARROW`), noted as `Popup::Reader` so the page behind dims; it fades in (`effects::fade_in` over `FADE_MS`) instead of opening out as other popups, its pictures kept out of the fade (a kitty picture's cells carry its id in their colour). Enter marks the article read, puts it in History, and shows the kept text or fetches its page (`App::body_of`, `feed::page`, `html::article_text` on a blocking thread: the element with the most paragraphs' text, as Firefox's reader view finds it; class names like `related` or `share` mark what's left out only inside it, since VnExpress's whole column is `sidebar-1`). Its pictures come as `Block::Picture` in place (`html::picture_of`: `data-src`/`data-original`/`srcset` for ones that load late, not icons or logos by size or address, not a link's to another page; through `feed::picture_url`, at most `MAX_PICTURES`); kept texts start with `STORED`, and older copies are read from the page again. At the top: the picture and the title beside it (under it below `BESIDE` columns); scrolled, the head folds to a line (`FOLDED`). The text's pictures (`body_layout`, `Laid`) take blank rows at their own shape (`Images::shape` once decoded, 16:9 until then; at most 1.5× their size, four fifths of a page high) and are drawn with ratatui-image's `SlicedImage`, so they scroll a row at a time out of the top (kitty, sixel, blocks alike); the article's own picture isn't repeated (`same_picture`). Closing is at once, the screen behind brightening as after any popup. Frames of an animation are paced from when each began (`App::run`, `sleep_until`). `]` / `[` swap the article without it.

**Videos (`html::Video`, `App.playing`, `player.rs`, `pepper.rs`).** `html::article_text` finds them as it finds pictures, in place (`video_of`: a `<video>`'s `src`, `data-src` or `<source>`, a muted looping one being a GIF, so its poster as a picture; VCCorp's `VideoStream` div, its caption inside it; each with its box, `video_box`: what holds it and nothing of the text, whose picture is its poster, `poster_in`, and not a picture of its own), only elements that play one walked up from (`plays_video`), a `<video>` inside a player already found being that player's; the page's data giving the address of the same file (`named_videos`, matched by `file_stem`, a name long and with digits, not one every stream has as `playlist`: Dân Trí's `data-src` is a path its script rewrites); a muted looping `<video>`'s poster counts as one of `MAX_PICTURES`; with none in the text, the first the data names goes first (VnExpress's and VTC News's video pages), and a page with no text is that video. Kept as `v <url> [<poster>]` (`STORED` `v 3`: older copies are read from the page again, and a `v 2` one, `Block::decode_older`, shows as it was while its page can't be read or isn't on https; a video playing that a new text doesn't hold stops). The reader lays one out at its poster's shape but as wide as the column lets it, however small the poster (`Laid::video`, 16:9 with none; a shade with ▶ until it's there), with a line under it (`video_line`: what Enter does, or where and how far it plays, `ui::played`), and notes those it showed, whole first (`Reader.videos_shown`, cleared each frame, so a frame that showed none leaves none for Enter). Enter plays the one shown (`App::enter_video`: on the one playing, pause), `f` the full screen of the one playing (`fullscreen_video`; with none playing, a page as before, never starting one that scrolled into view), `x` stops it; with no video, Enter is the browser. A video whose poster is the article's own picture, first among the text's pictures, takes the head's picture's place (`same_picture`): it isn't shown twice. Leaving its article stops it (`open`, `close_reader`, quitting). `App::play_video` starts pepper-play inside Pepper (`inline_player`, a token from `pepper::new_token`), else mpv (`Tools::mpv`, `TN_MPV` or `PATH`; none: the reader says how to get it), as `player::Player` (Unix: controllable; Windows: started and stopped only, `fullscreen` as an option). mpv's `time-pos`, `duration`, `pause`, `playback-restart` (`Playing.started`) and `end-file` come back as `PlayerEventKind`, for the playback numbered `App.plays` only. Inside Pepper, each frame lays out `App.video_box`: the video's place in the text when it's all shown (`reader::draw_pictures`), else a box in the reader's corner (`reader::corner_video`, `pepper::pip_area`, black with "Loading" until its first frame), or with `f` (`Playing.fullscreen`, `App::fills_tab`) the whole tab but the status bar, which says how far it played and the player's keys, a message in their place (`ui::full_screen`, its animations' time moved on by `effects::under` as on any frame, or a popup over it never opens out; `on_fullscreen_key`: Space, ← →, ↓ ↑, `f` / Esc / `q` back, `x`; a paste opens no box behind it). No black box in the corner where the picture was taken away. Under a popup, a Pepper with holes gets the popups the frame drew (`App.drawn_over`, `ui::note_drawn_over`) as holes; an older one has the box taken away (`picture_shown`).

**Pictures (`images.rs`).** A card's or the reader's own picture is `Subject::Article`, cropped to fill its box (`Built::Whole`); one of an article's text is `Subject::Inline` (the hash of its address), built as a `SlicedProtocol` (`Built::Sliced`, `Images::get_sliced`) only once its shape is within `SHAPE_SLACK` of its box's, else `Built::Shape` records the shape and the next frame asks at its own. Under anything open over them (`App::covers_articles` for the cards, `popup_open` for the reader's), sixel and iTerm2 pictures aren't drawn. A kitty picture's first drawing puts the code that sends it in its first cell, which the reader, a popup or the corner video's box may then be drawn over, losing it for good; so `Images::place` takes it out of the cell (`take_transmit`, the placeholder kept) and `App::run` writes it right after the frame (`Images::take_transmits`), and only then is the picture `KittyImage.sent`. A terminal speaking kitty's protocol keeps every picture until told to delete it, and past its quota (320 MB in Ghostty and kitty) drops the first sent, the Home cards behind the reader; so `encode` numbers each kitty picture itself (`Images::next_kitty`, from a random start, since the programs in one terminal window share the numbers), any sent and dropped, however (`MAX_READY`, `MAX_SLICED`, a rebuild, the budget, `Images::drop_all` on quitting), has the terminal delete it (`KittyImage`'s `Drop`; `Images::deletions`, written before each frame by `App::send_deletions`), and after each frame (`Images::fetch`) those sent go back under `KITTY_BUDGET` bytes of pixels, the text's pictures going before the cards and never one the frame drew or asked for (`Images::keep_within_budget`). One the picker would resize is made by it, numbered at random, and never deleted (`encode`).

**UI (`ui/`).** As tuitube's: round-bordered panes, the one with the keys in the accent color; the search box in the articles' border; key hints in the status bar written with the keys in backticks (`hint_spans`, `hints_fitting`); the `?` popup with Keys and Settings tabs; `y`-to-confirm questions (`Confirm`); animations (`effects`: the intro, popups opening over a dimmed screen, the reader fading in). First, with animations on, the splash screen (`splash.rs`, as tuitube's): the logo (the feed icon's mark in white on `theme::LOGO`, the feed icon's orange on every theme, in half blocks, the largest of `LOGOS` that fits; "t u i n e w s" under it) drawn by `ui::splash::show` as soon as `main` has the terminal, so it's up while the terminal is asked how it draws images. `App::keep_splash` keeps it over the first frames: `ui::draw` draws each in full under it, so the pictures it shows are asked for, but `Images::hold` keeps sixel and iTerm2 ones from being drawn, as they'd be painted over it (kitty's are sent apart from the frame, their placeholders under it), and nothing else animates. It leaves once up `HOLD` (0.7 s) and the first screen is in (`App::first_screen_in`: the frame before missed no picture, `Images::missing`, failed ones not counted; and it had articles, or no feed is still coming), or up `MOST` (2 s), fading out over `OUT`; the fade at start then brings in the screen, its pictures all there. `grid.rs`: cards of at least `card_width` columns, the picture 16:9 in pixels but short enough that the words fit; `list.rs`: two rows an article; `sidebar.rs`: the logo in its border (`ui::logo`: the icon in white on `theme::LOGO` between half blocks, about square; the reader's border has it too), then "tuinews" in the text's color, the menu, then under rules the categories and the feeds under Feeds, with their unread counts (`!` when a feed's last fetch failed). Below `NARROW` columns the sidebar and the articles take turns.
