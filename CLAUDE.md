# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

tuinews: a terminal RSS reader for one person's own use, laid out as tuitube is (`../tuitube`: a sidebar, a grid of cards with real pictures, both arrow keys and vim keys), with a reader for articles' text. Rust, ratatui, tokio, MIT. Its groundwork is tuitube's, copied and cut down: `text::clean`, `config` (the private data folder), `screen` (taking the terminal and handing it back), `tmux`, `proxy`, `theme` and `themes/`, `icons`, `images`, `ui/effects.rs` and `ui/splash.rs` (its logo tuinews's own). Keep them in step with tuitube's when one changes; tuitube's CLAUDE.md says why each rule is there.

It starts with Vietnam's biggest news sites (`defaults.rs`, `FEEDS`) and categories made of those sites' sections (`CATEGORIES`: each section a feed of its own, not `listed`), put in the store once each (`Store::seed_defaults`, the `meta` rows `seeded` and `categories_seeded`), so what you remove doesn't come back. `a` adds a feed (in a category view, only into it), `x` in the sidebar removes one, `F` puts one in categories.

## Running

Use a separate data folder for trying things: `TN_DATA_DIR=$HOME/tn-test cargo run` (a full path; relative paths are refused). For checks, prefer tests that render into ratatui's `TestBackend` (`ui/mod.rs` tests, `app::tests::app()`: an in-memory store with the defaults and three articles, pictures offline). To see the real app without a terminal, run it in a pty with `TN_IMAGES=blocks` (any mode but `auto` skips ratatui-image's terminal query, whose thread keeps reading stdin when nothing answers, and takes the first keys typed). `docs/hero.png`, the README's picture, is one frame of made-up sites and articles (`hero.rs`, test-only; nothing real in it): `cargo test -- --ignored export_hero_screen` writes `target/hero/screen.json` (every cell, and where each card's picture went with the kind it is), and `tools/hero.py` draws it as Ghostty would (JetBrains Mono, Nerd Font icons, box lines to the cell edges), painting each picture itself. Tests that talk to the news sites are `#[ignore]`d: `cargo test -- --ignored live` fetches every default feed and reads an article's text from every site.

## Commands

```sh
cargo build
cargo test                       # offline tests
cargo test -- --ignored live     # every default feed, and an article's text from each site
cargo clippy --all-targets       # keep it warning-free
cargo fmt
```

## Security

Everything from a feed or a page is untrusted: titles, summaries, links, picture URLs, dates, HTML, image bytes.
- Links (an article's, a picture's, a feed's you add) are kept only through `article::checked_link`: `http`/`https`, a named host (`article::public_host`: no IP address however it's spelled, `localhost`, `.local`, `.lan`, `.internal`, `.home.arpa`), no user or password, at most `MAX_LINK`. Pictures are fetched only over https (`images::allowed`; `feed::picture_url` asks for https and for the JPEG behind an `.avif`). Redirects (`feed::client`) go only where `checked_link` lets a link go, never from https to http, at most `MAX_REDIRECTS`. An article's page is fetched only over https, only when it's opened, only if it's HTML, at most `html::MAX_PAGE`; feeds at most `feed::MAX_FEED`, pictures `images::MAX_BYTES`.
- Text: titles, sources, bylines through `article::one_line` (after `html::summary`, so markup and entities become text, twice-escaped ones too); summaries and articles' text through `html` (only text comes out: `SKIPPED` elements dropped, lists left out of summaries) and `article::lines`, with caps (`MAX_TITLE`, `MAX_SUMMARY`, `html::MAX_BODY`, `MAX_BLOCKS`). Text read back from the store is cleaned again (`store::article_row`, `Block::decode`), and a row whose id or link doesn't check out is skipped. A link in an article is text; nothing opens it. Only `o` opens a browser, with the article's checked link (`app::open_url`: `open` on macOS/Windows, `xdg-open` found as an absolute path elsewhere, its own process group, the home folder).
- Ids: `ArticleId` is the first 16 hex digits of the link's SHA-256, checked when read back (`ArticleId::parse`); cached pictures are named by it only (`a-<id>`).
- Pictures are decoded only as JPEG, PNG, WebP or GIF (`images::decode`), within `MAX_SIDE` and an allocation cap, WebP frame headers checked first (`check_webp`), a decoder's panic contained (`images::panic_is_contained`, checked by the panic hook).
- No cookies, no `Referer`, timeouts on every request; one proxy for everything (`proxy`: http or https only, else tuinews won't start).
- Pastes: only bracketed pastes and runs of different keys at once (`App::on_terminal_events`, `PASTED_KEYS`) are pasted text; they go in an open box, or open the add box with what looks like a link, never run as keys.
- The store (`tuinews.db`, 0600, `secure_delete`, a WAL checkpoint after removals) and `settings.toml` (written through a rename, one key at a time: `Settings::save_one`) are in the private data folder.

## Architecture

**Event loop (`app.rs`, `App::run`).** One `tokio::select!` over terminal events, `AppEvent`s (`Fetched`, `Page`, `Found`, `Image`, `Quit` on SIGHUP/SIGTERM) and a 1 s tick (status messages expire, feeds checked every `CHECK_EVERY`). After each wake, `needs_reload` reloads the view; after each frame, `Images::fetch` starts what the frame wanted.

**Feeds (`feed.rs`).** `refresh_feeds` fetches every feed older than `refresh_minutes`, `PARALLEL` at once, with its ETag and Last-Modified (`Fetched::Unchanged` on 304); a 429 pauses the feed for `SLOW_DOWN`. `parse` reads RSS 2.0, RSS 1.0 and Atom with quick-xml leniently (a mistake keeps what came before it), and Tuoi Tre News's own shape (`article` items, `headline`, a picture in `source`). Pictures come from the enclosure, `media:content`, `media:thumbnail`, `thumb`, then the first `img` of the description or content. Dates (`parse_date`): RFC 2822 with the zones Vietnamese sites write (`+07:00`, `+07`, `GMT+7`, two-digit years, written-out months), RFC 3339, and zoneless ones (Tuổi Trẻ's `10/24/2026 6:26:00 AM`) taken as Vietnam's time for a `.vn` site; a Vietnamese feed whose newest is hours ahead is put in Vietnam's time (`in_vietnams_time`: one of Tuoi Tre News's servers writes `+0000`). A feed carrying whole articles (`content:encoded`, Tuoi Tre News's `content`) gives their text too (`Item.body`, kept as if read from the page). `discover` adds a feed from a site's page (`html::feeds_named`).

**Store (`store.rs`).** SQLite: `feeds` (place, when fetched, ETag, Last-Modified, the last error, `listed`: under Feeds and in Home, else a section only in categories), `articles` (one per link, the feed that brought it first and its source name, published, first seen), `article_feeds` (every feed that brought each article: VnExpress's newest and its Xe section bring the same ones), `categories` and `category_feeds` (a feed in any number), `read`, `saved`, `history` (`HISTORY_SIZE`), `bodies` (articles' text, `Block::encode`). Unread counts count each article once (`COUNT(DISTINCT …)`). A date ahead of now is now. Removing a feed (`forget_feed`) takes it out of its categories, keeps the articles another feed brought or you saved or opened, and points an article it brought first at another; a section left in no category and not `listed` is removed (`forget_if_orphan`: after `set_in_category` off, `delete_category`). Category names are unique in any case, Unicode's, at most `MAX_CATEGORY_NAME`. `migrate` brings a version-1 database up (the `listed` column, `article_feeds` filled from `articles.feed_id`; `meta` `version`). Articles older than `keep_days` and in neither list are pruned at start. `Listing` names what a view lists (Home: articles of `listed` feeds); search is done here, over the newest `SEARCHED`, with `article::fold` (lower case, accents off).

**Views.** `View::{Home, Saved, History, Feed, Category, Search}`; `App::reload` rebuilds `App.feeds` (every feed; `App::listed` those under Feeds), `App.categories`, `App.home_unread` (`refresh_counts`) and `App.articles` from the store, leaving out blocked words and (with `unread_only`) what you've read, except what you read since the view opened (`read_here`), and keeps the selection on the same article, or on the newest while it's at the top, and the sidebar's row on the same category or feed (`row_of`). `App::show` switches views, pushing the old one on `back`.

**Categories popup (`F`, `App.category_menu`, `ui::category_menu`).** For the sidebar's feed, else the selected article's (`App::feed_of`: in a category view, the article's feed in that category, from `Store::feeds_of`), else none: the categories ticked where the feed is, then "New category". `Enter` / `Space` toggles (`toggle_in_category`; with no feed, opens the category), `n` names a new one (with the feed in it), `r` renames, `x` deletes after a `y` (`Confirm::DeleteCategory`, as `x` on a category in the sidebar). A name being typed (`Naming`) takes pastes, and counts as typing for `on_terminal_events`; one that won't do stays to be fixed.

**Reader (`App.reader`, `ui/reader.rs`).** A popup over the articles (`ui::reader_place`: `reader_width` + 12 wide, a row free above and below; the whole body below `NARROW`), noted as `Popup::Reader` so the page behind dims; it fades in (`effects::fade_in` over `FADE_MS`) instead of opening out as other popups, its pictures kept out of the fade (a kitty picture's cells carry its id in their colour). Enter marks the article read, puts it in History, and shows the kept text or fetches its page (`App::body_of`, `feed::page`, `html::article_text` on a blocking thread: the element with the most paragraphs' text, as Firefox's reader view finds it; class names like `related` or `share` mark what's left out only inside it, since VnExpress's whole column is `sidebar-1`). Its pictures come as `Block::Picture` in place (`html::picture_of`: `data-src`/`data-original`/`srcset` for ones that load late, not icons or logos by size or address, not a link's to another page; through `feed::picture_url`, at most `MAX_PICTURES`); kept texts start with `STORED`, and older copies are read from the page again. At the top: the picture and the title beside it (under it below `BESIDE` columns); scrolled, the head folds to a line (`FOLDED`). The text's pictures (`body_layout`, `Laid`) take blank rows at their own shape (`Images::shape` once decoded, 16:9 until then; at most 1.5× their size, four fifths of a page high) and are drawn with ratatui-image's `SlicedImage`, so they scroll a row at a time out of the top (kitty, sixel, blocks alike); the article's own picture isn't repeated (`same_picture`). Closing is at once, the screen behind brightening as after any popup. Frames of an animation are paced from when each began (`App::run`, `sleep_until`). `]` / `[` swap the article without it.

**Pictures (`images.rs`).** A card's or the reader's own picture is `Subject::Article`, cropped to fill its box (`Built::Whole`); one of an article's text is `Subject::Inline` (the hash of its address), built as a `SlicedProtocol` (`Built::Sliced`, `Images::get_sliced`) only once its shape is within `SHAPE_SLACK` of its box's, else `Built::Shape` records the shape and the next frame asks at its own. Under anything open over them (`App::covers_articles` for the cards, `popup_open` for the reader's), sixel and iTerm2 pictures aren't drawn.

**UI (`ui/`).** As tuitube's: round-bordered panes, the one with the keys in the accent color; the search box in the articles' border; key hints in the status bar written with the keys in backticks (`hint_spans`, `hints_fitting`); the `?` popup with Keys and Settings tabs; `y`-to-confirm questions (`Confirm`); animations (`effects`: the intro, popups opening over a dimmed screen, the reader fading in). First, with animations on, the splash screen (`splash.rs`, as tuitube's): the logo (the feed icon's mark in white on `theme::LOGO`, the feed icon's orange on every theme, in half blocks, the largest of `LOGOS` that fits; "t u i n e w s" under it) drawn by `ui::splash::show` as soon as `main` has the terminal, so it's up while the terminal is asked how it draws images. `App::keep_splash` keeps it over the first frames: `ui::draw` draws each in full under it, so the pictures it shows are asked for, but `Images::hold` keeps them from being drawn (a kitty picture is sent only with its first drawing, which the splash would cover), and nothing else animates. It leaves once up `HOLD` (0.7 s) and the first screen is in (`App::first_screen_in`: the frame before missed no picture, `Images::missing`, failed ones not counted; and it had articles, or no feed is still coming), or up `MOST` (2 s), fading out over `OUT`; the fade at start then brings in the screen, its pictures all there. `grid.rs`: cards of at least `card_width` columns, the picture 16:9 in pixels but short enough that the words fit; `list.rs`: two rows an article; `sidebar.rs`: the logo in its border (`ui::logo`: the icon in white on `theme::LOGO` between half blocks, about square; the reader's border has it too), then "tuinews" in the text's color, the menu, then under rules the categories and the feeds under Feeds, with their unread counts (`!` when a feed's last fetch failed). Below `NARROW` columns the sidebar and the articles take turns.
